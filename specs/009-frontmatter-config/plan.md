# Implementation Plan: Per-Note Frontmatter Configuration

**Branch**: `009-frontmatter-config` | **Date**: 2026-10-21 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from [`specs/009-frontmatter-config/spec.md`](./spec.md)

---

## Summary

Allow Markdown notes to persistently specify per-note label configuration via a structured `label` YAML frontmatter block (`template`, `customFields`, `qrCodeSize`, `fontSize`, plus layout and dimension overrides). The plugin parses and validates the frontmatter via Obsidian's native `MetadataCache`, applies overrides over template and global defaults while ignoring invalid fields with descriptive console warnings, renders `customFields` with ellipsis truncation on the label canvas, and documents the frontmatter schema in `README.md`.

---

## Technical Context

**Language/Version**: TypeScript 5.4+ / Node.js 18+ (Electron desktop runtime)  
**Primary Dependencies**: `obsidian` API (`MetadataCache`, `FileManager`), HTML5 Canvas, `jspdf`, `qrcode` (zero new external npm dependencies)  
**Storage**: Note YAML frontmatter in Markdown files + plugin settings (`data.json`)  
**Testing**: Jest 29+ / `ts-jest` unit and integration test suites  
**Target Platform**: Linux, macOS, and Windows (Obsidian Desktop)  
**Project Type**: Obsidian Community Plugin  
**Performance Goals**: Frontmatter parsing and validation in < 2 ms per note; zero extra disk reads by leveraging `app.metadataCache`  
**Constraints**: 100% offline, zero external YAML dependencies, backward-compatible with legacy flat frontmatter keys, graceful fallback on malformed YAML values  
**Scale/Scope**: Single-note generation, live preview, custom label modal persistence, and vault-wide batch label regeneration
